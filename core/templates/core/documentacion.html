Arquitectura, Despliegue y Modelo de Datos - TicSystem (Mesa de Ayuda)

1. Descripción General del Sistema

TicSystem es una plataforma de Mesa de Ayuda de nivel empresarial, diseñada específicamente para entornos hospitalarios y clínicos. Su objetivo principal es centralizar, gestionar y resolver las solicitudes de soporte técnico e incidentes reportados por los funcionarios.

El sistema abarca el ciclo de vida completo de un ticket, integrando la gestión de inventario tecnológico (activos), niveles de servicio (SLA), notificaciones automáticas por correo electrónico vía SMTP y métricas de resolución (Business Intelligence).

2. Arquitectura del Sistema

La aplicación está diseñada bajo una arquitectura moderna de microservicios contenerizados utilizando Docker y Docker Compose. Esto garantiza la portabilidad, escalabilidad y un entorno de ejecución idéntico tanto en desarrollo como en producción.

¿Cómo se comunican los componentes?

Todas las comunicaciones ocurren dentro de una red privada de Docker aislada del exterior. Nginx recibe las peticiones web y actúa como Proxy Inverso, enviándolas al contenedor Web (Gunicorn). El contenedor Web, así como el Worker de Celery, se conectan directamente al contenedor de PostgreSQL para la persistencia de datos y al contenedor Redis para la cola de mensajes en segundo plano.

Contenedor Web (Django/Gunicorn)

Contiene la lógica de negocio principal y las API. Expone la aplicación en el puerto 8000 internamente.

Celery Worker

Procesa tareas asíncronas pesadas en segundo plano (como el envío de notificaciones y cálculo de SLAs) para no bloquear la interfaz del usuario.

PostgreSQL (db)

Motor de base de datos relacional ejecutándose en la versión 15-alpine. Sus datos están persistidos en un volumen local.

Redis

Actúa como Message Broker para la comunicación asíncrona entre Django y Celery.

Nginx

Servidor web y Proxy Inverso que sirve los archivos estáticos y enruta el tráfico HTTP (Puerto 80).

3. Instalación y Despliegue

Configuración de Variables de Entorno

Toda la configuración de conexión y seguridad reside en el archivo oculto .env en la raíz del proyecto. El motor Docker Compose lee automáticamente este archivo al iniciarse.

Comandos de Control (Docker Compose)

Para administrar el ciclo de vida de la aplicación, utilice los siguientes comandos en el servidor de producción (ubicado en el directorio del proyecto):

# Levantar todo el proyecto en segundo plano
sudo docker compose up -d

# Ver los logs en tiempo real (todos los contenedores)
sudo docker compose logs -f

# Aplicar nuevas migraciones a la Base de Datos
sudo docker compose exec web python manage.py migrate

# Reiniciar únicamente los motores de procesamiento (Web y Tareas) tras un pase a producción
sudo docker compose restart web celery_worker

# Detener completamente la aplicación
sudo docker compose down

4. Credenciales de Base de Datos

La base de datos se ejecuta completamente aislada dentro del contenedor Docker ticsystem_db. Por estrictas normas de seguridad, el puerto no está expuesto directamente al host físico ni a internet, por lo que toda conexión externa debe realizarse a través de un túnel SSH o modificando temporalmente el docker-compose.yml.
